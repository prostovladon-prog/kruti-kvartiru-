Подробная карта кода: `docs/PROJECT_MAP.md`. Здесь только то, что нужно помнить всегда.

## Что это

Коллекционная игра-крутилка для Telegram Mini App (бот `@VoinyEpohBot`, канал `@voinyepoh`, чат `@voinyepohchat`).
Игроки крутят карточки воинов, собирают альбом, дерутся, торгуют, качают дракона, кланы, ивенты, казино за руны, Башня и т. д.
Владелец общается по-русски, отвечать по-русски. Аудитория 15–25 лет, есть несовершеннолетние (см. «Важные правила» в README).

## Как устроен прод

- **Клиент** (index.html + *.js + style.css + assets) отдаётся с **GitHub Pages** из ветки `main`: `https://prostovladon-prog.github.io/kruti-kvartiru-/`. Пуш в `main` = клиент обновился у игроков (кэш сбивается метками `?v=` в index.html).
- **Сервер** — свой VPS (`API_URL` в начале `game.js`: `https://77-221-147-102.sslip.io`). Там Node 22 запускает `server/node-server.mjs`, который грузит **`server/worker.js`** и использует SQLite (`/var/lib/voiny/game.db`) через обёртку с API как у Cloudflare D1. Код лежит в `/opt/voiny` (git clone этого репо).
- **Обновление сервера делает владелец** командой `voiny-update` на VPS (= `git pull --ff-only` + `systemctl restart voiny`). Я (Claude) только пушу в `main` и говорю, что нужен `voiny-update`, если менялся сервер.
- Секреты на VPS в `/etc/voiny.env` (BOT_TOKEN, ADMINS, DB_PATH, PORT). В репо секретов нет и класть их нельзя.
- Админ игры: Telegram id `6724818967` (`ADMINS` в `server/server.js`).
- Время в игре — **Минск (UTC+3)**. Все расписания, «дни», акции считаются по Минску.

## Обязательный порядок при любой правке

1. Правишь исходники. **Никогда не править `server/worker.js` руками** — он собирается.
2. Менял `rules.js` или `server/server.js` → `python3 tools/build_worker.py` (иначе VPS будет крутить старый код: он запускает именно worker.js из git).
3. Менял любой клиентский файл (`*.js` в корне, `style.css`) → `python3 tools/bump.py` (обновляет `?v=` в index.html и `version.json`).
4. `node tools/check.mjs` — должно закончиться `✅`. (Это же делает pre-push хук владельца на Windows.)
5. Для серверной логики по возможности — точечный тест (см. `server/*-test.mjs`) или быстрый прогон через `loadWorker()/openDB(":memory:")`.
6. Коммит в стиле conventional commits: `feat(tower): ...`, `fix(event): ...`, `chore(web): ...`, `balance(...)`, `perf(...)`. Обычно пушу прямо в `main` (так делает владелец). Крупное/рискованное — ветка + PR.
7. После пуша сказать владельцу: «клиент обновится сам; для сервера выполни `voiny-update`» (если трогал rules.js/server.js/worker.js).

Новый клиентский JS-файл: добавить `<script>` в `index.html` **и** имя в список в `tools/bump.py`.
Новая таблица/колонка БД: добавить SQL в массив `MIGRATIONS` в `server/server.js` и **увеличить `SCHEMA_V`** (сейчас 85). `ALTER TABLE ... ADD COLUMN` и `CREATE TABLE IF NOT EXISTS` применяются автоматически при старте. `server/schema.sql` — только базовые таблицы.

## Ключевая архитектура (коротко)

- `rules.js` — общие правила: данные (HEROES, отделки, шансы, цены) и `ACTIONS` (чистые действия над состоянием игрока). Работает и в браузере (офлайн-режим), и на сервере. `runAction(name, st, cards, ctx, p)`.
- Клиент вызывает сервер через `act(name, p)` в `game.js` → `POST {API_URL}/api` с JSON `{a, p}` и заголовком `X-Init-Data` (подпись Telegram). Ответ `{ok, res, S}`; `S` — новое состояние игрока, клиент кладёт его в глобальный `S`.
- Сервер `server/server.js`: `handle()` — большой роутер по `a` (рынок, чат, бои, арена, кланы, ивент `ev_*`, казино `cas_*`, Башня `tower_*`, оплата Stars `invoice/pay_*`, админка `adm_*` …). Всё, чего нет в роутере, уходит в `doAction()` → `runAction()` из rules.js с оптимистичной блокировкой (`users.ver`, до 8 попыток).
- Фоновая работа: `export default { fetch, scheduled, tick }`. На VPS `tick` раз в 5 с (турниры, Арена, Башня, ивент, автопосты), `scheduled` раз в 10 мин (напоминания бота).
- Бот: вебхук `/tg`, настройка `/setup`. Посты в канал и рассылки — из сервера, многие «одноразовые» по датам (ключи-защиты в таблице `kv`).
- Состояние игрока: строка `users.state` (JSON) + отдельные колонки (cash, vip_until, clan, …); карточки — таблица `cards` (каждая уникальна на весь мир: `sn` и `(h,f,no)`).

## Подводные камни

- Файлы огромные и местами минифицированы в длинные строки (game.js ~460 КБ, style.css ~520 КБ, server.js ~6000 строк). Искать через `grep -n`, читать кусками, не переписывать целиком.
- Индексы героев в `HEROES` постоянные — не переставлять и не удалять (на них ссылаются карточки в базе).
- Много разовых акций/постов «по дате» в server.js — новые делать так же: проверка времени по Минску + ключ в `kv`, чтобы сработало один раз.
- `server/local-test.mjs` на 25.11.2026 падает на строке ~714 (устарел после изменений) — не считать это поломкой моей правки; рабочие проверки — `node tools/check.mjs`.
- `quiz.js` в index.html не подключён (старая викторина).
- Ссылки внутри Telegram открывать через `tg.openTelegramLink`/`linkFor()/sendLink()`, не `window.open` (check.mjs это проверяет для event.js).
- Картинки для постов бота берутся с `raw.githubusercontent.com/.../main/...` — файл должен быть запушен до того, как сервер попробует отправить пост.
- Никаких чужих брендов/персонажей; платные случайные прокрутки за реальные деньги нельзя (см. README).
